# Reuse native-map setup in the complete full-history caller

The complete PR5447 direct-history caller takes **23.67% less wall time** with
an invocation-owned cache of exact native-map construction. Five alternating
fresh-process runs per side give medians of 1.279605 s and 0.976726 s. Baseline
range is 1.246776 to 1.304742 s; cached range is 0.961030 to 1.042614 s. All ten
complete executions succeed with identical scientific stdout bytes.
[BENCHMARK.json](BENCHMARK.json) is generated by the retained harness and binds
its source hashes.

Claim type: scoped implementation-preservation proof, finite conformance and
local performance evidence. This is a newly posed runtime question on the
unchanged predecessor caller. No new kernel theorem, kappa or supplier admission
is claimed.

## Change and preservation argument

The complete caller initializes three separate native registries for its
provider-backward, source-backward and source-forward cases. They request 216
native constructions but use only 58 distinct binary maps. The adapter reuses
158 exact results. It neither caches history rows nor shares native registries.

The pinned `monomial.native(columns)` function is deterministic. It reads nine
binary map columns and returns one immutable 1,024-byte signed permutation.
The key snapshots all nine columns, so equal keys have equal outputs. Each miss
calls the original function. Each hit returns the bytes that function would
construct. Mutating an input list cannot change a stored tuple key; callers
cannot mutate returned bytes. Exceptions are not cached. Capacity is 256 entries,
and the cache is cleared on every invocation exit, including exceptional exits.

Every `intern` call therefore receives the original bytes in the original order.
Operator IDs, products, scalar rows, histories and final output remain the same.
This implication does not depend on a small-width sample. The adapter
authenticates all seven external inputs before installing reuse and runs the
original `verify_kernel.py` unchanged. Its three complete cases, literal
permutation checks, equations, frozen-result comparison and four original
controls still execute.

## Evidence and measurement

The new verifier compares original and cached construction on 300 distinct
invertible nine-dimensional unitriangular maps. It checks full-key reuse,
256-entry capacity, eviction, mutable lists, restored contents and independent
cache owners. Six malformed inputs reject at the boundary. Two singular-map
executions retain the original exception and leave no cached value.

Both complete callers must agree byte for byte and match every field of the
predecessor's frozen result. Their stdout SHA256 is
`31116d29f77eaa5732cc76eb0c716c808f063c195e2aa886f4993ea33f51d29d`.
The cached path must record exactly 58 misses and 158 hits. The verifier
authenticates the generated measurement against its implementation, harness and
manifest, and recomputes the measurement summary. Timing itself is not a CI gate.

Local measurement uses CPython 3.12.15, standard library, macOS arm64 and 18
logical CPUs. Initial load averages were 2.86, 2.41 and 1.74; other work could
run concurrently. Alternating sides exposes both to that load. Their observed
ranges are disjoint. Each subprocess includes startup, authentication and the
entire direct caller inside the timed region. Baseline uses the same adapter
without installing reuse. Neither side skips checks or uses a cross-process
cache. All ten return codes are zero. Profiler runs are excluded from samples.

The initial complete profile identifies 216 `monomial.native` calls; a separate
cached profile has 58. Fraction arithmetic remains a larger cost after reuse.
The repeated setup is only part of the complete caller. This explains a bounded
end-to-end saving and does not predict a twofold speedup. The first improvement
is packaged without further arithmetic optimization.

## Reproduce

From the repository root on the recorded machine:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/native-history-setup-cache/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -O -B research/native-history-setup-cache/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/native-history-setup-cache
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/native-history-setup-cache --check-source-history
```

Direct status is `PASS_NATIVE_HISTORY_SETUP_CACHE`: 300 maps, eight rejecting
executions, two complete callers, 58 misses and 158 hits. Registered status is
`PASS_REGISTERED_RESEARCH_PACKAGE`. Other machines may substitute CPython 3.12.

Run the complete cached caller or generate a new measurement outside the checkout:

```sh
python3.12 -W error -B research/native-history-setup-cache/run.py --mode cached
python3.12 -W error -B research/native-history-setup-cache/benchmark.py --output /absolute/scratch/new-benchmark.json
```

The harness refuses to overwrite its output. For a diagnostic profile, insert
`-m cProfile -o /absolute/scratch/profile.pstats` before `run.py`. Profiler timings
are not comparable to the retained uninstrumented samples.

## Limits and code discipline

Timing is local to this complete direct caller and environment. Other PR5447
commands, selected cold replay, physical native admission, compiler closure,
ownership, precision/tape and analytic recovery remain unrun or inherited.
Independent human and formal proof-kernel review are unclaimed. No predecessor
source, credit line or selected-frontier file changes.

The adapter accepts nine integer columns in `[0,512)`; invertibility retains the
original check. Retained payload is at most 256 times 1,024 bytes plus bounded
keys and bookkeeping. Python allocation is a managed-runtime deviation from
fixed allocation. Finite loops are bounded by 300 maps, 36 triangular positions,
six malformed inputs and two singular executions. Benchmarking runs ten children
with 120-second timeouts. New functions fit within 60 lines. Standard import
loading and `runpy` load only the pinned modules, a bounded dynamic-loading
deviation with no generated code. Explicit exceptions remain active under `-O`.
Warning-strict normal and optimized replay supply the interpreted diagnostics.
